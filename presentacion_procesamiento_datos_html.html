Tema 01

Introducción al Procesamiento de Datos

El Desafío de la Era Digital

En la actualidad se generan zettabytes de datos desde sensores IoT, interacciones web, transacciones financieras, redes sociales y dispositivos móviles.

Los datos puros en su estado natural carecen de utilidad práctica directa. La ingeniería de sistemas provee los mecanismos para transformar este "ruido digital" en activos utilizables.

Tema 02

Concepto de Procesamiento de Datos

Es la técnica sistemática de recolectar datos de entrada, manipularlos mediante operaciones lógicas o aritméticas organizadas, y almacenarlos o transformarlos en un resultado estructurado de salida.

1. Entrada (Input)

Captura, lectura y validación de datos en bruto.

2. Procesamiento

Cálculo, clasificación, ordenamiento, filtrado y agregación.

3. Salida (Output)

Reportes, almacenamiento persistente, alertas o APIs.

Tema 03

Concepto de Dato

Definición Formal

Un dato es una representación simbólica (numérica, alfabética, algorítmica) de un atributo o variable cualitativa/cuantitativa.

const tempSensor = 39.5;
Propiedad Clave:

Carece de significado por sí mismo. No contiene intención ni contexto semántico explícito.

Atributos Técnicos de un Dato

  • Atomisidad: Unidad mínima e indivisible de representación.
  • Tipo (Data Type): Define el dominio de valores permitidos y las operaciones válidas (entero, flotante, booleano, string).
  • Representación en Memoria: Codificación binaria (ASCII, UTF-8, IEEE 754 para coma flotante).
Tema 04

Concepto de Información

Dato + Contexto = Información

La información es un conjunto de datos procesados, estructurados y puestos en contexto de modo que adquieren un propósito y utilidad directa para reducir la incertidumbre.

"La temperatura registrada en el servidor central #04 a las 14:00 hrs es de 39.5 °C (por encima del umbral crítico)."

Impacto en la Toma de Decisiones

Mientras que los datos se almacenan en bytes raw, la información permite emitir diagnósticos y ejecutar lógica condicional en un sistema informático.

Un sistema de monitoreo reacciona a la información, no únicamente a cadenas de bits aisladas.
Tema 05

Concepto de Conocimiento

Comprender los Patrones

El conocimiento surge al sintetizar múltiples fuentes de información, vinculándolas con la experiencia, reglas de negocio, modelos heurísticos y análisis comparativo.

Perspectiva Humana

Entender que si la temperatura del servidor excede los 39.5 °C durante tres días seguidos en las horas de mayor carga, el sistema de refrigeración está fallando o sobrecargado.

Perspectiva de IA y Machine Learning

Un modelo entrenado (red neuronal o árbol de decisión) extrae "conocimiento" en forma de pesos y hiperplanos capaces de predecir fallas futuras.

Tema 07

Datos según su Estructura

Estructurados

Esquema rígido (filas/columnas). Consultables directamente mediante SQL.

Tablas RDBMS, CSVs, Hojas de cálculo.

Semi-estructurados

No siguen esquemas tabulares, pero poseen etiquetas organizadoras (self-describing).

JSON, XML, YAML, NoSQL Documental.

No Estructurados

Sin formato o estructura predefinida. Representan >80% de los datos del mundo.

PDFs, Imágenes (PNG), Videos (MP4), Audios, Texto libre.
Tema 08

Definición de Estructuras de Datos

Una Estructura de Datos es una forma especializada de organizar, almacenar y gestionar datos en la memoria de un computador para que puedan ser accedidos y modificados de manera eficiente.

Complejidad Temporal: O(n)

Determina la eficiencia y el tiempo de ejecución que le toma a un algoritmo realizar búsquedas, ordenamientos e inserciones a medida que crece el tamaño de los datos.

Complejidad Espacial

Define el consumo de memoria RAM adicional requerido por la estructura para gestionar punteros, índices y referencias de soporte.

Tema 09

Clasificación de Estructuras de Datos

Por Gestión de Memoria

  • • Estáticas: Tamaño fijo asignado en compilación (ej. Arreglos).
  • • Dinámicas: Asignación dinámica en tiempo de ejecución (ej. Listas enlazadas).

Por Secuencia Lógica

  • • Lineales: Elementos adyacentes uno tras otro (Arreglos, Pilas, Colas).
  • • No Lineales: Conexiones jerárquicas o en red (Árboles, Grafos).

Por Persistencia

  • • Volátiles: Residen en la memoria RAM (se borran al reiniciar).
  • • Permanentes: Residen en discos/almacenamiento no volátil.
Tema 10

Definición y Ejemplo de Arreglos (Arrays)

Propiedades

Colección finita y homogénea de elementos almacenados en posiciones de memoria **contiguas**. Permite acceso directo O(1) mediante índices.

Index 0 10
Index 1 25
Index 2 42
Index 3 99
Ventaja: Acceso instantáneo | Desventaja: Tamaño fijo.
// Código de Ejemplo (C++) 
#include <iostream>

int main() {
    // Declaración de arreglo estático de 4 enteros
    int temperaturas[4] = {10, 25, 42, 99};

    // Acceso O(1) por índice
    std::cout << temperaturas[2]; // Imprime 42

    return 0;
}
Tema 11

Definición y Ejemplo de Lista Enlazada

Estructura Basada en Nodos

Colección dinámica donde los elementos no se almacenan de forma contigua. Cada nodo almacena el **Dato** y un **Puntero/Referencia** al siguiente nodo.

10
ptr
20
nullptr
Ventaja: Crecimiento dinámico | Desventaja: Búsqueda O(n).
# Código de Ejemplo (Python) 
class Nodo:
    def __init__(self, dato):
        self.dato = dato
        self.siguiente = None

# Creación de lista dinámicamente
cabeza = Nodo(10)
cabeza.siguiente = Nodo(20)

print(cabeza.siguiente.dato) # Salida: 20
Tema 12

Pilas Enlazadas (Stack - LIFO)

Política LIFO (Last In, First Out)

El último elemento en entrar es el primero en salir. Operaciones principales: push() (apilar) y pop() (desapilar).

Elem 1
Elem 2
TOP
Casos de Uso: Historial del navegador, Call Stack de ejecuciones.
// Pila en JavaScript 
class Pila {
    constructor() { this.items = []; }
    push(elem) { this.items.push(elem); }
    pop() { return this.items.pop(); }
}

const stack = new Pila();
stack.push("Página A");
stack.push("Página B");
console.log(stack.pop()); // "Página B"
Tema 13

Colas Enlazadas (Queue - FIFO)

Política FIFO (First In, First Out)

El primer elemento en entrar es el primero en salir. Operaciones principales: enqueue() y dequeue().

<-- Salida (Front)
1°
2°
3°
<-- Entrada (Rear)
Casos de Uso: Colas de impresión, Message Brokers (RabbitMQ).
# Cola en Python 
from collections import deque

cola = deque()
cola.append("Tarea 1")  # Enqueue
cola.append("Tarea 2")  # Enqueue

print(cola.popleft())  # Dequeue -> "Tarea 1"
Tema 14

Árbol Enlazado (Tree)

Estructura Jerárquica No Lineal

Compuesta por un nodo raíz y subárboles de nodos hijos. Cada nodo contiene un valor y referencias a sus nodos hijos.

Raíz
Izq
Der
Casos de Uso: Sistemas de archivos, DOM HTML, Índices B-Tree en BD.
// Nodo de Árbol Binario (Java) 
class NodoArbol {
    int valor;
    NodoArbol izquierdo;
    NodoArbol derecho;

    NodoArbol(int val) {
        this.valor = val;
    }
}
Tema 15

Tipos de Almacenamiento

Bloques (SAN / NVMe)

División en bloques de tamaño fijo. Alto rendimiento y baja latencia. Usado directamente por motores de Bases de Datos.

Archivos (NAS / NFS)

Organización jerárquica basada en directorios y carpetas compartidas en red.

Objetos (S3 / Blob)

Almacena datos como objetos con metadatos e ID único. Escalabilidad ilimitada en la nube para Big Data.

Tema 16

Bases de Datos Relacionales (RDBMS)

Modelo Relacional (SQL)

Basadas en esquemas estrictos con tablas interconectadas por claves primarias y foráneas. Garantizan propiedades **ACID**.

PostgreSQL, MySQL, Oracle, SQL Server

Garantía ACID

  • • A (Atomicidad): O se ejecuta la transacción completa o no se ejecuta nada.
  • • C (Consistencia): Transición válida entre estados de datos.
  • • I (Aislamiento): Transacciones concurrentes aisladas.
  • • D (Durabilidad): Persistencia garantizada post-commit.

Tema 18

Data Warehouse (DW)

Repositorio Analítico Centralizado

Diseñado para análisis de datos **estructurados** provenientes de sistemas OLTP. Optimizado para consultas complejas de Inteligencia de Negocios (BI).

Enfoque: Schema-on-Write (se define el esquema antes de guardar).

Tecnologías Modernas

Snowflake
Google BigQuery
Amazon Redshift
Tema 19

Data Lake

Almacenamiento en Formato Nativo

Guarda volúmenes masivos de datos **estructurados, semi-estructurados y no estructurados** sin requerir transformación previa.

Enfoque: Schema-on-Read (el esquema se aplica al consultar).

Riesgo: Data Swamp

Sin gobernanza ni calidad de datos adecuada, un Data Lake se degrada rápidamente en un "pantano de datos" inútil e inasequible.

Tema 20

Data Lakehouse

Lo Mejor de Ambos Mundos

Arquitectura moderna que combina la **flexibilidad y bajo costo del Data Lake** con el **control transaccional ACID y gobernanza del Data Warehouse**.

Tablas ACID

Delta Lake, Apache Iceberg.

Consultas Directas

Motor SQL sobre almacenamiento de objetos.

Soporte IA / ML

Acceso directo para data scientists.

Tema 21

Definición General de Procesamiento

Transformación Algorítmica

El Procesamiento es la ejecución secuencial o paralela de instrucciones automatizadas que aceptan estados iniciales y producen estados derivados mediante lógica determinista.

Estado A (Entrada) ➔ Transición (Función f(x)) ➔ Estado B (Resultado)

Tema 23

Tipos de Procesamiento de Datos

Centralizado

Un único servidor o mainframe realiza todo el cómputo.

Distribuido

Múltiples nodos en clúster (Apache Spark) dividen la carga.

Tiempo Real

Procesamiento inmediato sub-segundo para respuestas instantáneas.

Por Lotes (Batch)

Acumulación previa y procesamiento masivo programado.

Tema 24

Procesamiento por Lotes (Batch)

Características

  • • Alta latencia, pero alto throughput (volumen/tiempo).
  • • Se ejecuta sin intervención humana en horarios programados (ej. 2:00 AM).
  • • Eficiencia óptima de cómputo sobre grandes dataset estáticos.

Casos de Uso e Impulsores

Cálculo de nóminas, generación de reportes mensuales, entrenamiento de modelos ML.

Tecnologías: Hadoop MapReduce, AWS Glue, Apache Spark Batch.
Tema 25

Procesamiento en Streaming

Flujo Continuo de Eventos

Procesa datos en tiempo real registro por registro a medida que son generados por las fuentes.

Latencia: Milisegundos / Segundos

Herramientas Clave

Apache Kafka
Apache Flink
AWS Kinesis
Tema 26

Arquitectura Lambda

Unión de Batch + Speed

Patrón híbrido diseñado para balancear precisión y latencia.

Data Sources
Batch Layer (Precisión)
Speed Layer (Tiempo Real)
Serving Layer (Consultas)
Permite responder consultas históricas precisas y eventos en vivo simultáneamente.
Tema 27

Microbatch

Enfoque Híbrido

Divide el flujo continuo de datos en pequeños paquetes dispersos en ventanas de tiempo muy cortas (ej. cada 500 ms).

Flujo Continuo ➔ [ Batch 500ms ] ➔ [ Batch 500ms ] ➔ Procesamiento
Ejemplo: Spark Structured Streaming (modo predeterminado).

Tema 29

Ingesta de Datos

Definición

Proceso inicial de transportación de datos desde fuentes heterogéneas hacia un sistema de almacenamiento centralizado.

Modalidades

  • • Pull: El pipeline solicita los datos activamente mediante APIs / CDC.
  • • Push: La fuente envía eventos directamente al receptor (Webhooks, Agentes IoT).
Tema 30

Pipeline de Datos (Data Pipeline)

Tubería Automatizada

Cadena programada de elementos de procesamiento de software que traslada datos del punto A al punto B aplicando transformaciones intermedias.

Origen Ingesta Transformación Destino Analítico
Herramientas de Orquestación: Apache Airflow, Prefect, Dagster.
Tema 31

ETL (Extract, Transform, Load)

1. Extract

Extracción de fuentes operacionales (Bases relacionales, APIs).

2. Transform

Transformación de datos en servidor intermedio **antes** de cargar.

3. Load

Carga final en el Data Warehouse estructurado.

Tema 32

ELT (Extract, Load, Transform)

Paradigma Moderno Cloud

Los datos crudos se cargan **directamente** en el Data Lake / Warehouse y se aprovecha el cómputo distribuido de la nube para transformarlos **in-situ**.

Ecosistema Modern Data Stack

Desacoplamiento total entre almacenamiento y cómputo.

Herramienta Estándar: dbt (data build tool)

Conclusiones
